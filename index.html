What this site is

A chapter-based path through latency engineering, built around one physical deadline. A parcel passes a scanner and reaches a diverter some distance downstream; belt speed times that distance is the time the controller has to sense, decide and act. Every chapter asks whether its technique fits inside that scan-to-divert budget, and answers with a measured distribution. The book starts with measurement (percentiles, coordinated omission, HdrHistogram), asks whether a garbage-collected runtime can hold a tight tail, works through the hot path and the threading and I/O models of C++, Python and Java, then goes beneath the code to the real-time Linux kernel, CPU partitioning and kernel bypass. From there it treats transport as a latency decision (gRPC, DDS, Aeron and SBE, FIX, Kafka, Modbus), shows how to observe a low-latency system without slowing it down, and closes with a failure model and a whole-line build that holds command latency while the data path is flooded. Everything on a critical path is open source. It assumes you can read at least one of the three languages; it isn't a tutorial in any of them.
